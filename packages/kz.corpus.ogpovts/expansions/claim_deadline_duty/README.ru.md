# Обязанность над требованием со сроком дела: стороны одной посылкой

`law.expansions.claim_deadline_duty` 0.1.0 — профиль `law.expansion/0.2`
(§279.2, [DECISION-0209](../../../spec/decisions/0209-expansion-profile-0-2-deontic-heads.ru.md) §8 этап 7, пилот Р8).
Каркас формы глав 16, 26 и 28 Закона об ОГПО ВТС: требование о выплате
связывает предмет, контекст (происшествие), выгодоприобретателя и
страховщика одной 4-арной посылкой; день получения и срок — двумя
2-арными посылками над требованием; условия — над требованием; цель —
над требованием.

## Контракт

`bearer`, `beneficiary`, `matter`, `context`, `start`, `due` —
связыватели; `claim: relation(matter, context, beneficiary, bearer)` —
посылка требования в порядке позиций акта (`payment_claim_of(demand,
accident, holder, insurer)`); `started`, `due_on` — `relation(matter, Date)`;
`conditions: list<relation(matter)> min 0`; `result: relation(matter)`.
Порождаются два узла, окно `[start, due]` включительно; политика §86 не
нужна. Связыватель `context` в цели не участвует: он нужен только посылке
требования — так каркас обходит ограничение профиля «аргументы meta-literal
— связыватели», не вводя `_` (DECISION-0209 §8 этап 7).

## Чего определение не делает

- Не выводит срок и не читает `effective` из акта — экземпляр объявляет
  `effective` сам (ст. 17 п. 2 пп. 7-3: с 01.01.2027).
- Не принимает стороны двумя посылками — для этого `matter_deadline_duty`.
- Не устанавливает нарушение без установленного неисполнения (§136 п. 3).

## Пример и тесты

`examples/synthetic/`: страховщик отвечает на заявление о споре в срок с
получения. Тесты §267: ACTIVE, SATISFIED, VIOLATED при отрицательном факте,
условие требования отсекает позицию.

Пример вымышлен; потребитель в корпусе — `kz.corpus.ogpovts` (главы 16, 26, 28).
